# XminD IoT Protocol Selector

## 📡 MQTT یا HTTP؟ کدام پروتکل برای پروژه IoT شما مناسب‌تر است؟

یک ابزار آموزشی تعاملی برای کمک به دانشجویان، مهندسان و علاقه‌مندان به IoT جهت درک تفاوت‌های بین **MQTT** و **HTTP** و انتخاب پروتکل مناسب برای پروژه‌شان.

این ابزار همراه آموزشی یک پست اینستاگرام از **XminD** درباره انتخاب پروتکل ارتباطی در پروژه‌های IoT است.

1. فایل `index.html` را در مرورگر خود باز کنید:

4. سایت شما در دسترس خواهد بود:

## 🧠 موتور امتیازدهی

### نحوه کارکرد

ابزار از یک سیستم امتیازدهی شفاف استفاده می‌کند که بر اساس پاسخ‌های کاربر به ۵ سؤال، امتیازات MQTT و HTTP را محاسبه می‌کند.

### سؤالات

1. **تعداد دستگاه‌ها** - چند دستگاه قرار است به سیستم متصل شوند؟
2. **تعداد مصرف‌کننده‌ها** - داده‌ها چند مصرف‌کننده دارند؟
3. **مدل ارتباطی** - Request/Response یا Publish/Subscribe؟
4. **ارتباط دائمی** - آیا دستگاه‌ها باید ارتباط دائمی داشته باشند؟
5. **REST API** - آیا Backend شما REST API دارد؟

### منطق امتیازدهی

هر گزینه امتیازاتی برای MQTT و HTTP دارد:

```javascript
{
    text: '10 تا 100 دستگاه',
    scores: { MQTT: 3, HTTP: 1 },
    reason: 'تعداد دستگاه‌ها زیاد است'
}
```

امتیازات بر اساس موارد زیر تعیین می‌شوند:

- تعداد دستگاه‌های بیشتر → امتیاز بالاتر برای MQTT
- چندین مصرف‌کننده → امتیاز بالاتر برای MQTT
- نیاز به Request/Response → امتیاز بالاتر برای HTTP
- ارتباط دائمی → امتیاز بالاتر برای MQTT
- وجود REST API → امتیاز بالاتر برای HTTP

### تولید پیشنهاد

پس از محاسبه امتیازات:

1. درصد هر پروتکل محاسبه می‌شود
2. پروتکل با امتیاز بالاتر به عنوان پیشنهاد اولیه نمایش داده می‌شود
3. دلایل انتخاب بر اساس پاسخ‌های کاربر جمع‌آوری می‌شوند
4. یک توضیح جایگزین نیز ارائه می‌شود (که پروتکل دیگر هم می‌تواند مناسب باشد اگر...)

**نکته مهم:** نتیجه به عنوان "پیشنهاد اولیه" ارائه می‌شود، نه "تنها انتخاب درست".

## 🔧 افزودن پروتکل‌های جدید در آینده

کد به گونه‌ای طراحی شده است که به راحتی می‌توان پروتکل‌های جدید اضافه کرد:

### 1. افزودن به آبجکت PROTOCOLS

در `script.js`:

```javascript
const PROTOCOLS = {
    MQTT: { ... },
    HTTP: { ... },
    // پروتکل جدید:
    CoAP: {
        id: 'coap',
        name: 'CoAP',
        fullName: 'Constrained Application Protocol',
        color: '#...',
        description: '...',
        strengths: [...],
        weaknesses: [...],
        useCases: [...]
    }
};
```

### 2. به‌روزرسانی سؤالات

امتیازات هر گزینه را به‌روز کنید:

```javascript
{
    text: 'گزینه',
    scores: { MQTT: 2, HTTP: 1, CoAP: 3 },
    reason: '...'
}
```

### 3. به‌روزرسانی UI

- جدول مقایسه را گسترش دهید
- نمودارها را اضافه کنید
- فلوچارت تصمیم‌گیری را به‌روز کنید

## 🎯 هدف آموزشی

این ابزار یک **مرجع مطلق** برای انتخاب پروتکل نیست، بلکه یک **راهنمای آموزشی** است که به کاربران کمک می‌کند:

1. تفاوت مدل‌های ارتباطی را درک کنند
2. عوامل مؤثر در انتخاب پروتکل را بشناسند
3. با تصور اشتباه رایج آشنا شوند
4. تصمیم آگاهانه‌تری بگیرند

### پیام کلیدی

> **MQTT جای HTTP را نمی‌گیرد.**
> **HTTP هم جای MQTT را نمی‌گیرد.**
> 
> **پروتکل را بر اساس معماری سیستم انتخاب کن، نه بر اساس اسم "IoT".**
